# 客人資料製作

> 這是**挖空模板**。標 ★ 的地方要你自己填，每一格都要寫「理由」。
> 填好之後，AI 每次幫你做客人都會照這份規則，不用你每次重講。

## 什麼時候用

使用者說「幫我做一批新客人」「我要出題考同學」時。

## 每位客人必須有這些欄位

| 欄位 | 意思 | 限制 |
|---|---|---|
| name | 名字 | 不可用真實名人、不可重複 |
| intro | 一句話介紹 | 20 字以內 |
| budget | 一餐的總預算 | 30～150 的整數 |
| wants | 想吃的東西，有先後順序 | 1～2 樣，只能從菜單選 |
| hates | 討厭的東西 | 最多 1 樣，沒有就寫 null |
| days | 出現在第幾天 | 1～5 的整數陣列，例如 [1, 3] |
| count | 當天的基本人數 | 1～12 的整數 |
| lines | 五種情況的台詞 | 每句 20 字以內，五句都要有 |

`lines` 的五種情況：

- `bought`：買到了
- `hated_on_menu`：討厭的東西有上架，不進門
- `not_on_menu`：想吃的沒上架
- `sold_out`：想吃的賣完了
- `too_expensive`：太貴不買

## 菜單（只能從這六樣選）

招牌鍋貼、韭菜鍋貼、玉米鍋貼、酸辣湯、豆漿、紅茶

## 這批客人的主題

★ 主題：夜市挑剔客（中等龜毛）——逛夜市、很會比價、嘴很挑的客人，例如只喝無糖的、聞到韭菜就走的、錢包只剩銅板的。
★ 理由（為什麼選這個主題？）：這批客人要拿去和同學交換。夜市客人「愛比價、有明確好惡」很合理，可以用預算和討厭的菜考驗同學的定價與上架判斷；但難度維持中等，只要認真看預告和台詞就推理得出來，同學玩得下去，不是單純整人。

## 預算範圍

★ 這批客人的預算要落在幾元到幾元之間（必須在 30～150 之內）：40～110 元
★ 理由：鍋貼建議售價 70～80 元、飲料 25 元，一份鍋貼加一杯飲料大約 95 元。上限 110 元：照建議售價買得起一套，但定價拉高就會有人只買一樣或不買。下限 40 元：鍋貼最低只能定 50 元，預算 40 元的客人只會買湯或飲料，逼同學思考要不要上架便宜的品項。

## 工作步驟

1. 先讀 `web-lab/src/game/menu.js`，確認菜單與建議售價
2. 先產生 3 位客人，用表格給使用者看，**不要直接寫檔**
3. 使用者說 OK，才寫入 `web-lab/src/game/customers/my-customers.json`（整個檔案是一個陣列）
4. 寫完執行下面的檢查，逐條回報結果

## 寫完必須檢查

- 必填欄位都有，五句台詞都有
- budget 在 30～150 之間，也在上面填的預算範圍內
- wants、hates 只用菜單上的品項
- 沒有重複的名字
- 每一天的 count 加總不超過 50
- 在 `web-lab` 資料夾執行 `npm run check`，確認「客人包檢查」仍然全部 PASS
- 打開遊戲，在「客人包」選「我的客人包」，確認沒有出現紅色錯誤
- ★ 我自己加的檢查規則：每位客人的預算，至少要買得起他想吃的第一樣菜的「最低定價」（對照 menu.js 的 minPrice）；而且 hates 不可以和自己的 wants 是同一樣菜。
- ★ 這條規則要擋掉什麼樣的客人：不管店長怎麼定價都不可能賣給他的「必敗客人」（例如預算 40 元卻只想吃玉米鍋貼），以及「想吃又討厭同一樣菜」這種自相矛盾的客人。龜毛可以，但要有解。

## 不准做的事

- 不准新增菜單沒有的品項
- 不准新增欄位或修改遊戲規則
- 不准改 `my-customers.json` 以外的檔案
- ★ 我自己加的禁止事項：台詞不准直接說出數字答案（例如「超過 60 元我就不買」「我預算 80」），只能用語氣暗示（例如「這價錢我要考慮一下」「銅板不太夠」）。
- ★ 理由：規則書說台詞是「推理的線索」。直接講數字等於把答案給同學，就不好玩了；用暗示的方式，同學還是推理得出來，符合「中等龜毛」的難度。
